# Virtual Multi-Pak: four Slots, each a Pak; the Becker port belongs to the board

A Pak is a named profile: an optional ROM image plus the emulated devices it needs and their settings. A Slot is one of four positions; the slot register picks the Slot that owns the ROM window and /SCS. The Becker port is not in any Pak: it is the board's own circuitry, as a real Multi-Pak's is, so it stays reachable whatever Slot is active. Today's single ROM is the only Slot and no slot code exists; the decision fixes the shape that `picoco.cfg` and the Manager screens grow into, so the first multipak change does not re-argue it. On a Pico 2 build a Pak can only hold devices under /CTS or /SCS (ADR 0002 gates the data buffer on those); self-decoded $FF60-$FF7F devices are a Plus-W extra via JP2 2-3.
